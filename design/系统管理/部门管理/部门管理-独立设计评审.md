## 部门与组织关系（实施前契约）
- **组织**（已有 md_organization）：企业 / 工厂 / 车间 / 产线等真实组织层级与业务运营单元，不删除、不重命名原有字段。
- **部门**（拟新增 sys_department）：内部职能部门（如药剂科、制剂室、QC 室等）；部门有独立编码/名称、隶属组织主数据引用、上级部门、负责人、联系电话、状态、排序和说明。
- **用户所属部门**：由用户和部门的真实关联维护；系统原 sys_user 为全局账户且没有部门字段，不能把部门名写入 user displayName，也不能用角色代替部门关系。推荐增量 sys_user_department(org_id,user_id,department_id)，显式组织隔离，一个组织范围内每人一个主归属部门；历史用户允许 NULL/未分配。更复杂兼职关系留待明确需求。
- **业务人员资格**（md_qualification）和**角色权限**仍独立；部门设置不可绕过资格、安全、GxP、IAM 最小权限。
- 上级部门必须属于同一组织，不允许把自身或任何后代设为上级；已存在用户/子部门的部门不允许物理删除，只允许停用。
- 负责人通过用户选择器取值，所属组织通过既有主数据选择器查询，不存任意文本，也不在前端写静态名单。
- 如果新部门方案与现有冻结契约冲突，需保留历史审计并记录批准的业务增量，Flyway 只能追加 V040+ 迁移；不得变更 V001–V039。

## 设计评审记录（第一轮）
- 已人工检查查询与编辑图，发现结果表末端“查看编辑”间距不足、表头技术说明多余；已修改 CSS 和 HTML 并重新渲染。
- Chromium 自动检查查询/新增/编辑/查看 4 个场景，所有可编辑字段均为左标签右控件，不上下拆行。
- 1440×900 下页面无整页横向溢出，新建/编辑居中弹窗可见并有取消/保存操作。
- 重要剩余项：预览的静态部门树还没有真实数据绑定；从真实用户和组织接口加载的选择器、后端保存/校验、部门与用户关联、真实页面截图比对均未完成。
