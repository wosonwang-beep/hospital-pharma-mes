# 数据字典设计图独立视觉与交互评审（PC）

## 设计源及范围
- 源：`数据字典-设计原型.html` + `数据字典-设计.css`，不是当前生产业务页面。
- 设计截图：`数据字典-查询.png`、`数据字典-新增.png`、`数据字典-编辑.png`、`数据字典-查看.png`、`数据字典-字典项配置.png`。
- 设计目标：1440×900 PC，全局视觉采用已有 Global UI V2 的简洁白色/浅灰/医疗蓝；列表 T1，表单 T2，详情 T3，字典项配置为桌面主从维护页。
- 所有字典名称/数据均为**设计示例**；当前开发数据库尚未建数据字典表。

## 自主视觉评审
| 评审项 | 首次发现问题 | 修正及结果 |
|---|---|---|
| 结构 | 列表必须有筛选与数据表 | 查询、重置、主按钮、结果表、分页齐全；通过 |
| 表格 | 编码、状态、维护入口易区分 | 字典名称强调，编码等宽，颜色附带文本；通过 |
| 字典项编辑 | 右侧提交操作贴近屏幕底部 | 减少表单组间距、缩短不必要空白，保存/取消完整显示；修正后通过 |
| 表单 | 必填星号单独换行 | 必填星号与标签并排；修正后通过 |
| 编辑 | 类型和选项的保存动作容易混淆 | 类型编辑页独立，字典项独立进入配置页；通过 |
| 信息层级 | 避免无意义的副标题和内部技术元信息 | 列表页移除解释性副标题，不展示内部 ID/版本/审计 JSON；通过 |
| 使用逻辑 | 停用后是否可编辑历史名称 | 设计中明确提示“不再供新增选择、历史保留显示”；通过 |
| 宽度 | 1440px 是否遮挡横向页面 | 5 场景浏览器静态检查均无整个页面溢出；通过 |

**设计图静态视觉自评：通过（修正后）。** 此结论只适用于上述五张静态设计图，不代表页面已实现、更不代表实际业务验收通过。

## 下一阶段的实际实现验收点（必须真实执行）
1. 管理员在本地共享 MariaDB 新增字典类型与字典项，其他岗位按授权只读。
2. 字典项新增、修改标签、排序、启停后，真实业务表单无需重新部署便可加载最新选项。
3. 前端任何硬编码备用列表不得在 API 失败时偷偷接管；错误必须可见。
4. 修改已使用的编码要受到保护；停用项应支持历史业务回显，不会修改历史正式单据。
5. 通过真实 5173 浏览器截图再次与五张设计图逐页比较，并保存实施截图与差异修复证据。
6. 未有数据库迁移/真实接口/实际业务字段接入与通过上述验收前，系统功能状态：**待实施，不得标记验收通过**。
