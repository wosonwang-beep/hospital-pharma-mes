# 系统管理功能页面设计范围（先按本清单设计与审查）

用户确认的系统管理基础功能为：**部门、用户、菜单、角色、角色权限、数据字典**。六个功能不遗漏，数据字典不能用前端常量代替。

| 功能 | 待设计页面（PC） | 当前实现状态 |
|---|---|---|
| 部门管理 | 查询、增加、编辑、查看、部门树 | 当前有组织 `md_organization`，但尚无独立的部门实体与人员所属部门流程；待设计后实施 |
| 用户管理 | 查询、新增、编辑、查看 | 现有路由与组件，需按设计稿重审整改 |
| 菜单管理 | 查询、层级编辑、查看/子权限 | 现有数据库菜单方案正在整改，需回归真实角色授权 |
| 角色管理 | 查询、新增、编辑、查看 | 现有路由与组件，需优化视觉与交互 |
| 角色权限 | 角色功能授权树、菜单可见权限/普通操作/特殊操作配置 | 现与 `/admin/roles/:id/edit` 共享实现，可在设计阶段分别出图，再决定界面导航 |
| 数据字典 | 查询、新增、编辑、查看、字典项配置 | 本轮完成五张静态设计图及视觉自评，尚无数据库表/API/运行时页面 |

## 数据来源原则

- 部门、用户、角色、组织和仓库等实体选项走业务/系统主数据接口。
- 设备类型、物料类型等**经领域确认可配置**的类型值走数据库字典。
- GMP 状态机值、签名含义、权限代码及业务受控状态不属于可自由维护的普通字典；不可用“可配置”破坏安全规则。
- 新增数据字典、部门属于正式的数据库/API/权限/路由变更，须在设计图视觉评审完成后，走新增 Flyway 迁移；保留旧业务记录和权限。
- 所有页面 PC 1440×900，设计图存放各自中文功能菜单目录，最终设计图与真实页面同尺寸对照。未通过不得宣告完成。
