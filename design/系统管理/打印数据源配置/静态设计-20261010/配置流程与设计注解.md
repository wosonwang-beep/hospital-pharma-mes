## 2. 用户要维护的五层关系

```text
数据字典：业务类型 → 该业务下的单据类型
                           ↓ 分类
取数来源目录 → 数据源配置：主表 + 明细 + 关联
                           ↓ 选择与映射
                        打印字段
                           ↓ 现有引用方式
                        打印模板
```

- **业务类型**：例如WMS管理，来自现有树形字典根项。
- **单据类型**：例如收货单、出库单，是业务类型的子项。分类用于联动筛选和识别，不负责取数。
- **取数来源**：定义读哪个只读接口、传什么参数、返回根在哪里、完整字段结构是什么；可供多个数据源复用。
- **数据源配置**：将来源组合为一份可打印业务记录，说明主表、明细、关联如何取到。
- **打印字段**：从组合结果选择真实字段，配置稳定绑定键、名称、分组、格式、启用和顺序；由模板引用。

一个单据类型可有多个数据源；一个数据源可被多个模板使用。调用页面从正式菜单/页面登记选择，其记录ID映射到来源参数。不能用标签名称充当页面身份、记录ID或业务字段。分类下拉、来源目录、页面登记和字段元数据都应由数据库配置提供，例子不成为前端/后端固定清单。

来源方式是受控读取能力。本稿先落实业务只读接口流程；未来授权视图来源须有结构发现、组织隔离和只读契约，不能把任意SQL编辑器当成已经支持的功能。

## 3. 取数来源具体怎么配置

图02的编辑对象是“收货单查询”这一来源，不是“收货单模板”。

| 配置 | 收货示例 | 效果 |
|---|---|---|
| 来源编码/名称 | receipt-api / 收货单查询 | 来源目录中的稳定身份及可读名称 |
| 请求 | GET /api/v1/wms/receipts/{id} | 只调用已核准的本系统业务读取接口 |
| 参数 | id，路径参数，文本，必填 | 从调用页面/关联字段取得记录标识 |
| 响应根 | data | 从响应包装中提取业务对象 |
| 记录标识 | id | 明确哪一条是当前单据 |
| 返回结构 | 主字段和items集合的完整字段定义 | 配置页可选择所有真实字段，空明细仍保留结构 |

“读取接口结构”读取已登记完整schema；“导入结构”导入结构定义并检查路径、类型和集合层级；“添加字段”补充真实契约中已有的字段，不能凭空创造业务值。结构导入与试取响应是两件事：单条样例不能充当完整字段定义。接口参数、返回结构均可维护；服务端仍核验接口资格、角色、组织和逐条业务权限。图中“可访问角色”只能收紧配置可见范围，不能授予或替代原业务权限。

“检查取数”通过单据选择器选择真实业务记录，验证请求参数、响应根、结构和身份；当前静态稿的结果明确为示例。来源存在、元数据已配置不等于真实接口已接入。

## 4. 主表、明细和关联的配置操作

图03/04的“配置”按钮展开对应行下方的局部编辑区；取消恢复该行原值，确认后更新摘要，整页保存时才提交整体配置。局部编辑不新建业务页面结构，不单独写半套配置。

| 编辑区 | 可配置项 | 必须验证 |
|---|---|---|
| 主表 | 来源、记录标识、调用参数映射、返回对象定位 | 每个传入ID恰好一条主记录；拒绝无权限/多条主记录 |
| 主表数组明细 | 区域名称、别名、数组路径、行标识、排序 | 路径是集合；每行身份唯一；空集合仍可选字段 |
| 独立来源明细 | 区域名称、别名、来源、返回集合路径、参数映射、行标识、排序 | 例如将main.id映射到该来源已声明的receiptId查询参数；不得伪造不存在的接口 |
| 关联 | 别名、关联位置、来源、参数映射、本地键、目标键、ONE/MANY、未匹配处理、排序 | 本地/目标字段存在且类型兼容；每条明细分别关联；ONE多匹配报错 |
| 打印字段 | 结构选择、绑定键、名称、分组、格式、启用、顺序 | 路径真实存在；绑定键唯一；类型/层级不能通过改名伪装 |

关联位置可选择主表、明细区域或已登记关联节点；父依赖必须存在，不得出现循环。关联查询不仅显示“supplierId=id”，还要映射来源请求参数，如 supplierId → supplier-api路径参数id。独立明细亦须明确请求参数，不是只写数组路径。

“一对多”结果保留独立集合，可供模板明细区域选择，不与原明细做笛卡尔积。没有匹配时按配置留空或报错；出现多个匹配不能随意选第一条。数量以十进制精度处理，默认保留原值，格式只影响显示，不改业务事实。

“从结构选择字段”打开当前组合结构的树：主表、各明细、各关联。支持搜索、多选、显示样例、标记所属层级；选择后生成可编辑映射行。八个字段是本稿选中的示例，不是全部字段上限或内置白名单；原收货来源的其他已实现字段及现有模板键必须继续有效。“添加字段”也只能选结构中的真实字段或经批准的受控派生字段，不执行用户脚本。

## 5. 收货单完整配置例子

1. 数据字典维护WMS管理根项及收货单子项；其编码和既有WMS_RECEIPT身份保持兼容。
2. 登记收货单、供应商、仓库、单位只读来源及完整结构。
3. 新增数据源WMS_RECEIPT，选择WMS管理/收货单，绑定原辅料收货记录页面。
4. 主表选择receipt-api，传入选中记录id；明细items来自主表items集合。
5. 主表supplierId关联供应商来源id；warehouseId关联仓库来源id；每条items.unitId关联单位来源id。
6. 选择下列字段，试取并确认数量、单位、关联缺失和行数，再保存配置。

| 稳定绑定键 | 显示名称 | 取数路径示例 | 层级 |
|---|---|---|---|
| receiptNo | 收货单号 | main.receiptNo | 主表 |
| receivedAt | 收货日期 | main.receivedAt | 主表 |
| supplierName | 供应商名称 | main.supplier.supplierName | 主表关联 |
| warehouseName | 收货仓库 | main.warehouse.warehouseName | 主表关联 |
| materialCode | 物料编码 | items.materialSnapshot.materialCode | 明细 |
| materialName | 物料名称 | items.materialSnapshot.materialName | 明细 |
| receivedQty | 收货数量 | items.receivedQty | 明细 |
| unit | 单位 | items.unit.unitName | 明细关联 |

已确认来源快照中的供应商名称/物料信息应优先保持原事实；不得用今天的主数据名称覆盖历史。图中的main.supplier等为组合结果的命名空间，不宣称原业务接口直接返回该关联对象。现有reportNo、sequence等模板绑定键继续有效，不能只留下这八项。

## 6. 出库单完整配置例子

字典同一WMS业务根下维护出库单；配置WMS_ISSUE，绑定出库管理页面。主表读取已存在的 /api/v1/material-issues/{id} 结构；items为出库明细。每条items.materialLotId关联物料批次来源id，items.unitId关联单位来源id。

| 稳定绑定键 | 显示名称 | 取数路径示例 | 层级 |
|---|---|---|---|
| issueNo | 出库单号 | main.issueNo | 主表 |
| batchNo | 生产批号 | main.batchNo | 主表 |
| productName | 产品名称 | main.productName | 主表 |
| materialCode | 物料编码 | items.lot.materialSnapshot.materialCode | 明细关联 |
| materialName | 物料名称 | items.lot.materialSnapshot.materialName | 明细关联 |
| lotNo | 物料批号 | items.lot.lotNo | 明细关联 |
| issuedQty | 出库数量 | items.issuedQty | 明细 |
| unit | 单位 | items.unit.unitName | 明细关联 |

主表接口已有不代表关联来源、完整结构发现和真实打印资格均已实现；正式接入必须逐项验证。静态示例两行分别是12.5kg和3L，各自带L-001/L-002批号；不能仅按来源名称换标题仍使用收货字段。

## 7. 保存、试取与现有模板兼容

“试取数据”读取主表 → 明细 → 各级关联 → 映射，结果展示主表值、各集合、行数、原始值/格式化值、字段来源及逐项错误。接口失败、无权限、未匹配、多匹配、字段不存在、类型错误要定位到来源/区域/行/字段；不能只显示Invalid input或请求失败。

保存校验：分类归属有效、页面/来源启用、所有必填参数有映射、字段存在、别名和绑定键唯一、依赖无循环、行标识和排序明确、ONE/MANY符合结构。不能把失败试取显示为成功。停用来源后禁止新配置选择，历史只读引用仍可识别。

配置与来源元数据正式持久化在数据库，前端本地样例不作为正式数据。正式模型/API/迁移将在具体设计和原型批准后按有界补充同步；本稿不创建第二套字典基础设施，也不修改已执行迁移。

现有模板通过原来源身份/稳定键使用字段；数据源配置变更应追加可追溯版本，已有发布版本继续引用冻结配置，历史签名/PDF/打印证据保持不变。DOCUMENT按所选ID逐条打印单据；LIST将所选主记录作为列表行；两者仍由现有模板printType决定，配置页不增加另一套输出模式。
