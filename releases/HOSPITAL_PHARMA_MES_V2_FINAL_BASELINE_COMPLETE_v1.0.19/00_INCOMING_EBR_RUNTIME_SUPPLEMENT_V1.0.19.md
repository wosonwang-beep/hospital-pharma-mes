## Binding, storage and history

Release requires every frozen form to have an explicit operationDefId belonging to the selected frozen process route. A null binding fails 422 EBR_OPERATION_BINDING_REQUIRED with formCode; no first-operation assignment, duplicate-every-operation assumption, or placeholder operation. The release transaction creates one ebr_batch_snapshot per actual main batch and one form instance (occurrence_no=1) per bound form per actual operation. Repeating groups are value occurrences inside that form. No public create-instance route is added.

V018 creates the existing frozen ebr_batch_snapshot, ebr_form_instance, ebr_field_value_revision, ebr_rule_execution and ebr_review_record with common id/org/created_by/created_at/updated_by/updated_at/version_no columns, plus all business columns in v1.0.11 Database Design. ebr_form_instance.operation_execution_id FK is installed by V019, after the actual operation producer; initialization requires the actual execution port even before FK installation. Batch snapshot main_batch_id FK targets prd_main_batch. Form/field/review-rule IDs reference the exact effective source version; runtime values/labels/rules always come from batch snapshot, never a latest-version lookup. Mapping IDs to frozen stable codes is permitted; loading live mutable content is not.

Technical evidence additions to ebr_review_record: `form_revision INT NOT NULL CHECK >=0`, `review_rule_id BIGINT NOT NULL FK ebr_review_rule(id)`, `reason VARCHAR(1000) NOT NULL CHECK nonblank`, `signature_evidence_json LONGTEXT NOT NULL CHECK JSON_VALID`. Unique `(org_id,object_type,object_id,form_revision,review_rule_id)`. object_type is EBR_FORM_INSTANCE and object_id is the numeric form ID. The envelope is the exact immutable signed canonicalRecord/recordVersion/evidenceIds, with signatureId appended only after signing. Existing decision is PASS or REJECT; review_type remains VERIFY/APPROVE. The envelope, rule/revision, actor, decision, comment, reason and original signature are immutable; only complete invalidated_at/invalidation_reason evidence may be appended once. No physical review deletion.

Form uniqueness `(org_id,operation_execution_id,form_def_id,occurrence_no)`; revision begins 0 and changes once per successful draft save/correction, while version_no protects every mutable form update. Field revision uniqueness `(org_id,form_instance_id,field_code,occurrence_path,revision_no)`; revision_no begins 1 per field occurrence and previous_revision_id points to the immediate predecessor of the same form/field/path. Field and rule evidence are INSERT-only. `superseded` is derived from successor existence, never updated on the old field row. Legacy raw_value/derived_value remain nullable and unused; raw_value_json and normalized_value_json are the current facts. Unit IDs and source metadata are validated against the frozen field. There is no JSON blob replacing normalized field revisions.

Occurrence path is empty for a nonrepeating field/group, or `<groupCode>[<zero-based index>]` for a LIST group. Codes must match the frozen group; index must be within frozen maxOccurs, and active occurrence indices are contiguous from zero. The submitted form enforces minOccurs/maxOccurs and each required field within each existing occurrence. Removing a value appends explicit JSON null; it never deletes history. Unknown field/path, arbitrary sourceType, actor/time, derived/readonly/instrument spoofing is rejected. A normal draft request writes only MANUAL/BARCODE editable fields. Privileged correction preserves original source provenance and appends the correcting actor/reason; it does not claim a new device capture. Actual automatic inputs use a server-only append command with verified source identity and idempotency, not the public draft API.

## Runtime API, permission and DTO completion

All paths retain /api/v1 prefix and existing permissions. IDs are decimal strings, timestamps UTC, exact quantities remain decimal strings. Responses use ApiResponse on success and existing ApiError on failure. Writes require Idempotency-Key, reason and If-Match/formRevision agreement. Body formRevision is content revision; quoted If-Match is the same content revision for these legacy runtime endpoints, not definition version or mutable version_no. Reads return versionNo additionally for diagnosis, never a second editable token. Unknown/read-only fields are rejected. Companion incoming-runtime-openapi.json supplies typed schemas and replaces Generic references only for these existing runtime operations.

## State, evaluation and signatures

Initialization creates DRAFT revision 0. Draft saves require the real same-org operation IN_PROGRESS; append actual submitted field values and deterministic derived values, execute ON_CHANGE/ON_SAVE and retain results. Draft may preserve a failed required/range BLOCK as evidence; failure does not turn missing values into passing results. Submit requires DRAFT, current revision, active operation, and evaluates ON_SUBMIT against the exact frozen form and relevant cross-form inputs. BLOCK retains RuleExecution and returns 422 without transitioning; this controlled error is raised outside the evidence transaction after its 422 idempotency response is committed. No rolled-back failure is reported as retained. WARN is retained and may continue. deviation_trigger never fabricates an investigation; it calls an explicit real QMS deviation port, or fails closed EBR_DEVIATION_PRODUCER_REQUIRED. No browser executes DSL authority.

Successful submit sets SUBMITTED and server submitted_by/at. VERIFY/PASS reviews satisfy applicable frozen rules in sequence and lead to VERIFIED after all VERIFY requirements. APPROVE/PASS leads to APPROVED after all prerequisites and APPROVE requirements. With no review rules, SUBMITTED plus required signatures and passing rules is sufficient for operation eBR completion; no phantom review/signature is created. REJECT retains signed review evidence, blocks completion and returns form to DRAFT. A new submission following REJECT requires a new content revision (an audited draft save may restate unchanged values). Corrections append a new field revision, increment form revision, retain original values and return DRAFT for reevaluation; all affected valid review and form signatures are invalidated with reason in the same transaction. Scope dependency closure includes rules/reviews/signatures whose target fields depend on the corrected value; conservatively invalidating all evidence on that form is required at minimum. Cross-form dependencies invalidate dependent forms too; old evidence remains attributable. Correcting a completed operation requires the existing controlled reopening/change-control producer; absent that producer reject, never silently reopen production.

Register original platform object types EBR_FORM_INSTANCE and EBR_REVIEW_RECORD, meanings VERIFY/APPROVE only. Form signature uses objectId=form ID and recordVersion=current content revision; payload excludes mutable status/record token/review state, includes frozen definition hash and immutable current value revision IDs/raw+normalized values/unit/provenance. Later review-state changes do not invalidate that signature; value correction explicitly does. Provider checks current revision, matching frozen role/meaning requirement and real command permission; generic sign never transitions form state.

Review signing objectId is `<formId>:<formRevision>:<reviewRuleId>`, recordVersion=formRevision. Reauth binding uses actor/session/org/exact objectId/meaning/revision. Its transaction-scoped intent supplies canonical `{formEvidence,reviewRuleId,frozenRule,formRevision,decision,comment,reason,reviewerId}` before insert; the committed review stores the exact envelope. Generic verification loads the original envelope by the composite identity, verifies linked immutable signature/evidence and never reconstructs it from newer form values. A generic sign call without the controlled review intent is rejected. Required-role and independent-user policy apply to all original value authors, including overwritten revisions, and submitter where the frozen review requires it. No new signature enum or platform service is added.

Frozen policy scope resolves TEMPLATE to all bound forms; FORM to exact formCode; FIELD to owning form and that field; GROUP to its member fields; SECTION to groups and their fields. Sequences are enforced within the relevant scope and meaning/review type. Completion evidence enumerates exact satisfied review/signature IDs. Rules execute with server time/roles/status and existing conversion service; cross-form values resolve only inside the same execution/batch snapshot, never another execution's homonymous field.

## Java integration and UI

mes-ebr owns EbrRuntimeService.initializeOperation(org,actor,batchId,executionId,operationId,operationDefId,productionSnapshot), under MANDATORY existing transaction; same identity/content replay is safe, conflicting snapshot fails. EbrRuntimeService.requireOperationComplete/requireOperationReview and evaluateOperation return actual form/revision/signature evidence. An operation with no forms is complete only if the frozen definition assigns none to it, never when initialization is missing. Root boot adapters supply EbrExecutionPort operation/lockOperation plus operationIds and batchOperationIds; port returns exact batch/execution/operation IDs, states and immutable snapshot. No eBR -> execution -> production -> eBR dependency cycle.

Keep existing renderer/workbench routes. Render labels and inputs inline at desktop/mobile, group occurrence rows with explicit index, units and provenance visible, derived/device fields read-only, required/visible/rule messages driven by server model. Save and submit preserve unsaved input on 409/422; no auto overwrite. Correction opens the existing controlled reason/new-value interaction for a specific revision. Review selector shows only actual applicable frozen rules and required role; signature dialog shows form/revision/hash/rule/decision, actor, reason and reauthentication. History shows original/corrected values, superseded linkage and invalidated review/signature evidence. PDF route is retained for MES-013 archive completion; no generated fake PDF URL or fabricated manifest.
