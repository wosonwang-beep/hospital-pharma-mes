## Domain and state
Organization hierarchy: ENTERPRISE→FACTORY→WORKSHOP→LINE. ENTERPRISE has no parent; other types require a same-organization ACTIVE parent of the immediately preceding type. Codes are unique within org_id. Parent cycles are forbidden. Organization types and codes are immutable after creation; reparenting requires compatible parent and every descendant to remain compatible. ACTIVE→INACTIVE uses DisableOrganization; INACTIVE→ACTIVE uses EnableOrganization. Disabling a node with ACTIVE children is rejected. Historical references remain readable.
Unit codes are immutable; dimension is a nonempty controlled string, scale 0–12. Dimension changes on units referenced by conversions are rejected UNIT_DIMENSION_IN_USE to preserve controlled conversion integrity. Conversion factor is a positive decimal string, maximum DECIMAL(24,12); from/to units must exist in the same organization and differ. Cross-dimension conversions require material_id. Conversion chooses the exact material-specific pair before the generic pair, never another material; no implicit reciprocal/transitive conversion. Results preserve original value, factor, converted value and target scale (HALF_EVEN). Before LG-004 is physically installed, material-specific conversion writes are rejected DEPENDENCY_NOT_READY. LG-003 creates nullable material_id without its forward FK; LG-004 validates existing rows then adds the physical FK to md_material through a new migration. No early material table is allowed.
Equipment initial ACTIVE; ACTIVE→MAINTENANCE through BeginMaintenance; MAINTENANCE→ACTIVE through ReturnToService; ACTIVE|MAINTENANCE→INACTIVE through DisableEquipment; INACTIVE→ACTIVE through EnableEquipment. Codes immutable. Gate evaluated in UTC at the execution instant: ACTIVE and calibration_due_date absent or >= execution UTC date; otherwise 422 EQUIPMENT_UNAVAILABLE/EQUIPMENT_CALIBRATION_EXPIRED with requiredActions. md_equipment.location VARCHAR(200) NULL supplies the UI location column; it is descriptive text, not a WMS location reference.
Qualification initial ACTIVE; ACTIVE↔INACTIVE through explicit EnableQualification/DisableQualification. user_id references sys_user; inclusive UTC valid_from/valid_to, null endpoints unbounded. Gate checks same organization, user, exact qualification code, ACTIVE and execution UTC date; failures use 422 QUALIFICATION_REQUIRED and requiredActions. Codes/user are immutable. Validity updates are audited.

## API, permissions and GxP
Existing GET/POST/PUT paths and permission codes are retained. POST typed bodies create initial ACTIVE records. PUT accepts a typed command `action` and requires If-Match (quoted/unquoted nonnegative version) or body versionNo; conflicting supplied versions are rejected 400. Organization actions UPDATE/ENABLE/DISABLE; unit and conversion UPDATE only; equipment UPDATE/ENABLE/DISABLE/BEGIN_MAINTENANCE/RETURN_TO_SERVICE; qualification UPDATE/ENABLE/DISABLE. UPDATE changes editable descriptive/validity fields, never status directly. Unknown properties/enums rejected 400. IDs are strings, decimals strings, timestamps UTC. GET lists accept page (0-based), size (1–100), keyword, status where applicable, resource-specific filters, and sort by a server whitelist; same-org scope applies to all reads/writes and references.
All writes require Idempotency-Key, reason on updates, optimistic locking and AuditEvent in the same transaction. Replays do not duplicate audit/business facts. Permission checked before replay. No physical deletion. No new electronic-signature point: inherited platform signature ownership/required points are retained; MES-003 records are not fabricated signable objects. Errors use existing ApiError plus requiredActions for gates. Public consumer query/gate services return domain data, never API envelopes. Execution modules call them later; MES-003 does not implement future operation/weighing workflows.
