# MES-008 implementation contract for approved sequencing DCP

This integration handoff must be incorporated into the approved v1.0.17 baseline before implementation; it is not a second source of truth. The companion JSON provides 35 phase operations (MES-008A timeline and eligibility operations are deferred), their exact existing permissions, DTOs and phase availability.

All IDs and decimal quantities are strings; versionNo is an integer optimistic token. Dates use YYYY-MM-DD, timestamps UTC ISO-8601. Responses are existing ApiResponse envelopes, data contains the named schema. Lists return items/total/page/size (zero-based page, default 20, maximum 100). Every mutation requires Idempotency-Key; update/confirm/movement requires If-Match or versionNo (when both present they must agree) and nonblank reason. HTTP 200 success, 400 malformed input, 403 missing permission, 404 absent or other-org object, 409 conflict/stale/idempotency/state, 422 gate/dependency/reference failure. No DELETE.

Warehouse/location/container default ACTIVE; UPDATE edits descriptive fields, ENABLE/DISABLE are explicit commands. Receipt DRAFT allows UPDATE and CONFIRM, confirmed receipt is APPROVED and has no ordinary actions. A draft PUT atomically saves all header/item input, preserves prior items as audit evidence without deleting regulated records, and adds no stock. At confirmation current usable material, approved supplier relationship (not necessarily preferred), active matching warehouse/location/container, valid UOM conversion, dates, and all six PASS receipt checks are required. Confirmation snapshots current material and inspection policy, records actor/time, creates exactly one MaterialLot and RECEIVE entry per item atomically with audit. Both inspection-required and inspection-exempt lots start QUARANTINE/BLOCKED; only MES-008A may release them.

The draft receipt item rows keep stable item IDs by position; saving may not remove existing rows (existing regulated rows are never physically deleted). New rows can be appended. Once confirmed, items and snapshots are immutable. Inputs intentionally omit materialVersionId and retired material names. Item materialSnapshot contains only the current material basic snapshot. packageCount is a positive integer; quantity is a positive decimal with at most 6 places. Package specification remains textual and does not imply an invented quantity-per-package conversion.

Inventory quantities and ledger entries use the receipt-time snapshot baseUnitId. Every adjustment and movement explicitly converts input unit with current material-specific UOM rules and requires exact representability in decimal(18,6), no rounding loss. Balances are sums of immutable entries by lot/location/container/unit. Lot row optimistic locking serializes all lot movements; negative stock and FROZEN/expired/retest-due lots are blocked. A blocked quarantine lot may move physically without being made eligible. MOVE adds paired MOVE_OUT/MOVE_IN; ADJUST appends a signed delta with reason. No movement changes quality/inventory status. Source fields are server-derived; they cannot be supplied to bypass the receipt.

POST /inventory/receive accepts ReceiptCreate and executes the same receipt/check/snapshot/lot/RECEIVE workflow atomically as a direct receipt command under its original wms:receipt:create permission. Generic POST/PUT /material-lots retain original permissions but in this stage return 422 RECEIPT_REQUIRED (their full write acceptance remains deferred), preventing a second unaudited lot origin or ordinary mutation of quality/snapshot. All material-issue writes retain original permissions and return 422 DEPENDENCY_NOT_READY until the actual MainBatch and MaterialEligibilityService contracts are implemented. Read-only issue list/detail work on their durable tables (empty initially). No fake production batch or release provider is installed. Eligibility GET belongs to MES-008A and is not implemented in this stage. GET /main-batches/{id}/reservations uses wms:reservation:view and returns persisted reservations (empty until dependencies exist); POST uses wms:reservation:create and fails closed with DEPENDENCY_NOT_READY in this stage. Its table and future consumed contract are preserved.

Lookup sources: /warehouses, /locations?warehouseId, /containers (wms:inventory:view), /materials (master:material:view), /suppliers (master:supplier:view), /units (master:uom:view). Receipt list filters supplierId/warehouseId/recordStatus; lot list materialId/qualityStatus/inventoryStatus; stock list materialLotId/locationId. allowedActions is state-based and must also be filtered against user permissions. Lot allowedActions=[MOVE,ADJUST] only when not frozen/expired; eligibility is always denied in this phase. Example receipt item: {"materialId":"1","lotNo":"LOT-001","receivedQty":"5.000000","unitId":"1","locationId":"1","packageCount":1,"packageCheckPassed":true,"sealCheckPassed":true,"labelCheckPassed":true,"damageCheckPassed":true,"contaminationCheckPassed":true}.
