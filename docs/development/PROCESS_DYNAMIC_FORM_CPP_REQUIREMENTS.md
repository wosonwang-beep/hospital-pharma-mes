# 生产工艺动态表单 CPP 规则配置需求

状态：`APPROVED REQUIREMENT / NOT IMPLEMENTED`  
需求编号：`PROC-CPP-001`  
批准记录：[DCP-PROCESS-DYNAMIC-FORM-CPP-001](DCP-PROCESS-DYNAMIC-FORM-CPP-001-APPROVED.md)

## 1. 目标

在生产工艺的工序配置中，为动态表单提供可视化 CPP（关键工艺参数）规则设计能力。工艺工程师应能直接引用当前表单字段建立可读、可冻结、可在生产执行阶段判定的规则，而不重复维护产品适用关系或手写不安全表达式。

## 2. 角色与前置条件

- 主要角色：具有现有生产工艺/动态表单维护权限的工艺工程师。
- 前置条件：已进入一个生产工艺及其工序；当前工序已有动态表单定义和至少一个可引用字段。
- 状态约束：只有现有规则允许编辑的当前定义可以维护 CPP；只读或冻结状态仅展示。

## 3. 功能需求

### 3.1 双页签设计器

动态表单设计器必须包含且仅在同一设计器内切换：

1. 表单设计：维护字段、布局和字段属性；
2. CPP规则设计：基于当前表单字段维护 CPP 规则。

CPP 不是独立菜单，也不是独立产品配置页面。

### 3.2 当前动态表单字段

- 显示当前表单名称/版本及其可引用字段；
- 每个字段至少显示名称、数据类型和单位；
- 字段选择以稳定字段编码为内部引用；
- CPP 页签不得新增字段、修改字段编码、类型、单位或其他字段定义；
- 字段被规则引用后，表单设计变更必须执行引用完整性检查，禁止产生悬空引用。

### 3.3 规则基本信息

每条 CPP 规则包含：规则编码、规则名称、规则描述、启用状态和显示顺序。规则名称必填，描述用于解释工艺目的。

CPP 规则不提供“适用产品”字段。适用产品由生产工艺已有关系确定。

### 3.4 可视化条件配置

- 条件项由“字段、比较运算符、比较值”组成；数值字段同时显示单位；
- 支持 `AND`、`OR`；
- 支持条件组及嵌套组合；
- 支持至少 `>`、`>=`、`<`、`<=`、`=`、`!=`，具体可用运算符按字段数据类型限制；
- 不允许用户输入 JavaScript、SQL、SpEL 或其他任意可执行代码；
- 保存前校验字段存在、类型匹配、单位兼容、条件组非空和表达式可解析。

示例：

```text
(灭菌温度 >= 121℃ AND 灭菌温度 <= 125℃)
AND 灭菌时间 >= 20min
```

### 3.5 规则预览

设计器同时生成：

- 业务可读预览，例如“121℃ ≤ 灭菌温度 ≤ 125℃，且灭菌时间 ≥ 20min”；
- 系统表达式预览采用现有安全 DSL，例如 `value('ster_temp') >= 121 && value('ster_temp') <= 125 && value('ster_time') >= 20`。

预览只反映当前配置的确定性转换，不使用生产数据运行规则，不展示“运行校验效果”。

### 3.6 超限动作

每条规则可组合配置本次批准的四类动作：标记异常、禁止提交、生成偏差记录、要求 QA 复核。

动作的实际触发、权限、签名、审计、幂等和事务边界由生产/eBR 执行阶段负责。设计器不得伪造执行结果。

### 3.7 保存与冻结

- 保存时同时持久化条件树、规范化系统表达式、业务可读预览和动作集合；
- 提交/生效前执行静态 lint；
- 生产下达时按现有规则将 CPP 定义纳入对应工艺/eBR 冻结证据；
- 新版本规则不得改变在制或历史批次已冻结的规则和执行证据。

## 4. 业务关系

```text
产品 ──适用──> 生产工艺 ──包含──> 工序 ──配置──> 动态表单
                                                   └──引用字段──> CPP规则
```

不得新增“产品 ↔ CPP规则”的直接关系。产品切换、工艺适用范围和版本生效均继续由生产工艺维护。

## 5. 异常与反馈

- 无可引用字段：显示空态并引导返回“表单设计”页签；
- 字段引用失效：阻止保存/提交，并定位规则和条件项；
- 类型或单位不匹配：阻止保存并给出字段级原因；
- 并发修改：沿用现有乐观锁冲突处理；
- 无权限或状态不可编辑：服务端拒绝，页面只读且不得仅依赖前端控制。

## 6. 验收标准

- 同一动态表单设计器准确呈现两个页签；
- CPP 页签只能引用当前表单字段且无新增/修改字段入口；
- 页面无产品选择器，产品适用关系可由生产工艺链路追溯；
- AND、OR、条件组能生成等价的业务预览与安全 DSL；
- 四类已批准超限动作可配置并可被序列化；
- 页面不存在“运行校验效果”区域或设计期真实数据运行入口；
- 字段删除/修改、非法表达式、单位不兼容、空条件组均被阻止；
- 历史发布定义和批次冻结证据不被改写。

## 7. 非功能与合规

- 遵循 Global UI V2 和生产工艺专用编辑器的桌面端设计约束；
- 所有标签与控件同行，条件组具备清晰的层级、键盘操作和错误定位；
- 所有关键保存、提交、生效和执行结果沿用现有审计、签名、权限、组织隔离和幂等要求；
- 规则求值必须确定、可复现、可版本化，禁止任意代码执行。
