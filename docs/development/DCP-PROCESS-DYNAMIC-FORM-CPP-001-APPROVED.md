# DCP-PROCESS-DYNAMIC-FORM-CPP-001 — 生产工艺动态表单 CPP 规则设计（已批准）

状态：`APPROVED / DESIGN BASELINE / NOT IMPLEMENTED`

## 1. 有界变更范围

本变更只调整生产工艺功能中“工序 → 动态表单设计器”的设计基线：

- 动态表单设计器固定包含“表单设计”和“CPP规则设计”两个页签；
- CPP 规则只引用当前动态表单已有字段，不在 CPP 页签新增或修改字段定义；
- CPP 规则不直接绑定产品。适用产品关系由“产品 → 生产工艺 → 工序 → 动态表单”链路确定；
- CPP 支持规则基本信息、可视化条件配置、规则预览和超限动作配置；
- 可视化条件支持 `AND`、`OR` 和嵌套条件组；
- 删除设计期“运行校验效果”区域。实际判定和动作仍发生在生产/eBR 执行阶段。

详细需求见 [PROCESS_DYNAMIC_FORM_CPP_REQUIREMENTS](PROCESS_DYNAMIC_FORM_CPP_REQUIREMENTS.md)，详细设计见 [PROCESS_DYNAMIC_FORM_CPP_DETAILED_DESIGN](../architecture/PROCESS_DYNAMIC_FORM_CPP_DETAILED_DESIGN.md)。

## 2. 页面定位和结构

页面位于生产工艺详情/维护的工序配置工作区，不新增独立顶层菜单。当前工序的动态表单设计器结构为：

```text
生产工艺
└── 工序
    └── 动态表单设计器
        ├── 表单设计
        └── CPP规则设计
```

“CPP规则设计”页签由以下区域组成：当前动态表单字段、规则基本信息、条件配置、规则预览、超限动作。不得出现产品选择器和“运行校验效果”。

## 3. 业务边界

- 字段来源：当前选中工序的当前动态表单；字段编码是规则引用的稳定标识。
- 产品适用：沿用生产工艺已有适用产品关系；同一工艺下的 CPP 规则随工艺/工序/表单定义生效。
- 编辑状态：仅可编辑的当前定义允许维护；提交/生效后的定义遵守现有冻结、新版本、快照、审计和签名规则。
- 表达式安全：继续使用现有白名单 DSL；禁止 JavaScript、SQL、SpEL、网络/文件访问、反射及任意代码执行。
- 运行边界：设计页负责配置和静态校验，不模拟或展示生产运行结果；执行阶段按冻结定义动态判定并保留证据。

## 4. 超限动作

按用户最终选定设计，本次支持以下四类动作：

- 标记异常；
- 禁止提交；
- 生成偏差记录；
- 要求 QA 复核。

“阻止工序完成”“要求电子签名”不在本次最终批准页面范围内；后续如需增加，另行批准。

动作必须由服务端按冻结规则执行；前端显示或隐藏不能替代权限、状态、签名、偏差和审计门禁。
