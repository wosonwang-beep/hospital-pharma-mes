# 供应商资格状态中文化与独立停用控制 · 已确认设计

- 确认依据：2026-10-11 用户明确确认「供应商的状态是合格、不合格、待评审」「代码里的 APPROVED / UNAPPROVED / INACTIVE 全部修好，不得用英文代表含义」，随后答复「对」。
- 权威基线：FINAL BASELINE v1.0.23 + 本次有界业务变更；旧冻结迁移不修改。
- 本次范围：供应商资格字段、原有数据无损状态映射、供应商管理接口及页面、物料来源资格闸口、回归测试。
- **唯一业务资格取值（存储、API、页面、字典统一）**：`待评审`、`合格`、`不合格`。仅数据交换所必需的技术字段名（如 qualificationStatus）保留英文标识，字段值和用户可见含义不使用英文代号。
- 新供应商必为`待评审`；不得自动赋予「合格」，仅在真实资格评审通过后通过「评审合格」动作进入合格状态。待评审评审不通过转不合格；已合格复核不通过转不合格；已合格/不合格重新评审转待评审。普通资料编辑不得顺便批准或改变资格。
- **停用/启用为独立管理控制**：新增 `enabled` 布尔标志，停用不等于不合格。只有启用且资格为「合格」、证照及对应供货关系有效的供应商可用于收货及首选供应商。
- 历史主数据迁移映射：`APPROVED → 合格`；`UNAPPROVED → 待评审`；`INACTIVE → 待评审, enabled=0`（旧停用不可视为不合格）。本地预检当前 6 家 APPROVED、1 家 UNAPPROVED、0 家 INACTIVE；迁移后各自 ID/供应商名称/关联不变；不得伪造评审结果。
- 新增固定数据字典 `SUPPLIER_QUALIFICATION_STATUS`，三个中文代码/显示值：待评审、合格、不合格；不开放未定义状态。
- 既有的内部 HTTP 动作 `UPDATE`、`QUALIFY`、`DISABLE` 作为兼容操作标识保留，新增 `REJECT`、`REVIEW`、`ENABLE`；对用户呈现中文动作名称。这些动作不是资格状态，也不作为 UI 显示内容。
- 既有 `md_material_supplier.approved` 是「某物料与某供应商的供货关系有效」布尔字段，不是供应商资格状态，不做错误替换；历史受控电子签名与放行证据不重写。
- 不扩大到其他模块的英文状态枚举；用户要求中文化的是供应商资格取值。
- 迁移策略：只增 V054，不编辑 V008、V039 或既有 Flyway。验证约束、供应商 ID/数量、物料关系、组织隔离、WMS 不合格拒绝闸口、前端/后端测试。
- 用户此前要求补齐的模拟开发基础数据仍必须业务可信；尚无合格评审依据的候选企业不得被自动标「合格」。业务字段不得出现测试/演示/模拟等占位词；测试集身份放在外部报告、环境和元数据中。

**设计锁定**：仅上述状态及闸口修复获授权，既有所有其他业务模型、权限范围、UI V2/T1–T6 均不变。
