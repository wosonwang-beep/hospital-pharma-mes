# 按钮顺序规范变更 — 重要功能在左，辅助功能在右（2026-11-02）

Status: **USER APPROVED / ACTIVE**
变更类型：UI 规范条款变更（仅动作顺序，不涉及业务、字段、权限、状态、接口、数据库）
取代条款：[GLOBAL_T1_T2_UI_UNIFICATION_20261013](GLOBAL_T1_T2_UI_UNIFICATION_20261013.md) 第 15 行、第 26 行的动作顺序

## 1. 用户决定

用户于 2026-11-02 明确要求修改按钮顺序规范，原话：

> 两个按钮的先后顺序重要功能在左边，辅助功能在右边，如查询-重置，保存，取消/返回

结论：动作区**重要/主操作在左，辅助/次要在右**。此前 2026-10-13 确定的 `重置 → 查询`、`取消 → 保存/提交` 作废。

## 2. 生效条款

通用原则：同一动作区内，**重要的、推动流程向前的动作排在左边；辅助的、放弃/回退的动作排在右边**。

| 页面模板 | 动作区 | 顺序（左 → 右） | 对齐 |
| --- | --- | --- | --- |
| T1 查询/列表 | 查询条件卡动作组 | `查询 → 重置` | 右对齐 |
| T2 新增/编辑 | 表单动作区（sticky 或稳定区） | `保存/提交 → 取消/返回` | 右对齐、位置稳定 |

- 查询按钮保持主按钮（primary）处理；重置保持默认/普通按钮处理。
- 保存/提交保持主按钮；取消/返回保持默认或 ghost。
- 动作组整体右对齐，窄屏时整组换行，不得拆散按钮或改变组内顺序。
- 三类按钮以上（如 `保存 → 提交审核 → 返回`）按重要性从左到右递减排列。

## 3. 适用范围与例外

- 适用：普通 T1 查询/列表页、普通 T2 新增/编辑页。
- 特殊专用界面（生产执行 T5、QA 决策 T6、生产聚合 T4、eBR 表单设计器、打印可视化设计器、打印数据源映射编辑器、菜单权限配置、电子批记录目录编排器）保留各自已批准的动作集与排布，本条不强制其顺序；但其内部如出现「主操作 + 放弃操作」并列，仍建议遵循同一阅读方向。

## 4. 实现影响（供后续开发参照，本次未改代码）

- Ant Design Vue 的 `a-modal` 默认 footer 顺序为「取消 在左、确定 在右」，`a-popconfirm` 同样，与本规范相反；相关弹窗需通过 `footer` 插槽或自定义按钮显式反转顺序。
- 页面内自绘动作区（`<a-space>` / 按钮组）需检查声明顺序，DOM 顺序即视觉顺序，不依赖 `order`/`flex-direction` 反转。
- 前端当前无统一的查询按钮组共享组件（`frontend/mes-web/src/components/` 下仅有 `DictionarySelect.vue` 与 `printing/`），各页面自行声明，需逐页核对。
