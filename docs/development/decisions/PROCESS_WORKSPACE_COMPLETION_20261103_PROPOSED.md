# 生产工艺完整收尾方案

状态：PROPOSED / 待用户对具体冲突与实施边界确认。此文件不是已批准设计锁、原型批准或最终验收。不修改历史已批准文件，不切换 v1.0.23 权威指针。

同一功能 PROC-FORM-CPP-EBR-001，同一 Planning 0df9356d-675b-4f37-8b7d-948948c8d694；累计修复 50，不清零、不另立任务。完整差异和直接源码依据见 [交付核对](../process-form-cpp-ebr/20261101-final/WORKSPACE_DELIVERY_MAP_20261103.md)。

## 1. 拟确认的收尾方向

1. 保留用户指定的「上方路线带＋左侧工序＋右侧配置」，当前工序只有「工序设置 / 记录表单 / 参数与判定」三个局部分区，复用现有 Canvas、CPP 和 eBR 能力。
2. 工艺沿用已批准的「当前定义」维护：启用/停用与配置是否完整分别展示；保存当前定义，不恢复工艺版本创建/提交/批准及生效批准日期。eBR 自身版本、审批、签名及历史均保持原合同。这项需对旧原型相反的描述明确取舍，不把两套生命周期混合实现。
3. 为保留原型核心识别信息，建议把「工艺名称、工艺说明」补为真实字段，名称绝不拿产品名称替代。新增元数据只服务当前工艺识别；既有工艺编码、主键及历史快照不改。具体合同草案见第2节，批准前不写库、不创建正式迁移。
4. 工序上下移仅改变展示顺序，不自动改写前置依赖。多前置、分支、未配置 IPC 的工艺都合法；已有逐工序检验、有效 FAIL 阻断、必检签名及独立复核保持。
5. 已保存工序与参数不能物理移除或改码；新建未保存项可移除。复制只复制维护定义，产生唯一新工序编码，不复制表单归属、检验结果、签名、执行证据或物理 ID。
6. 新增/编辑参数和检验项采用居中弹窗；当前工序设置使用专用主从工作区，保持原型构图。共享查询/动作顺序、标签同行、父草稿保护遵循已批准全局交互规范。

## 2. 名称与说明有界合同草案

- 复用 proc_package，追加 nullable `package_name VARCHAR(200)`、`description VARCHAR(1000)`；存量为 NULL，不按产品或编码生成名称，不更新受控历史。
- 对新界面创建要求填写工艺名称；旧客户端不传新字段继续兼容，历史空名明确显示「未命名（历史工艺）」并以真实编码定位，不伪造名称。说明可为空。
- 现有 POST /process-packages 接收可选 packageName/description；GET 列表、详情返回当前元数据，空值明确为 null。既有 keyword 搜索扩展到编码、名称、说明，沿用服务端分页/组织隔离，按原有中文搜索方式实现，不扩大权限。
- 现有 PUT /process-packages/{id}/current-definition 增加可选 basicInfo `{packageName, description}`，在同一事务中与 route 保存；缺省/null basicInfo 不修改元数据。提供 basicInfo 时 packageName 必须非空且<=200；description 为 null/空表示清除，非空<=1000。不会用两次请求造成名称成功、路线失败的半保存。
- 既有 PUT /process-packages/{id} 仍仅承担原停用命令，不挤入新的通用状态更新。权限沿用 process:package:create/view/edit；既有 package:update 停用权限不变。
- 元数据不成为新的质量、审批或版本状态；基本维护仍沿用当前定义无客户端版本/无新增人工原因的合同。缺省字段不改变现有快照规范化内容；旧冻结 JSON/hash、历史签名/审计和 eBR 引用完全保留。是否在后续新冻结快照追加名称须在详细设计中明确，不默认改 canonical 输入；本候选只授权当前查询元数据。
- 只能使用新的 append-only 物理迁移；实施前查询同一 DEV 最高成功 Flyway 版本并检查并行任务占用，不预定版本、不修改 V071/V074 或其他既有迁移。同期更新 Domain/API/OpenAPI/UI/权限映射/RTM/迁移/消费者合同与一致性审查。

## 3. 完整动作与验收边界

| 交付项 | 正常路径 | 必须保留的异常与恢复 |
| --- | --- | --- |
| 工作区 | 列表→查看/编辑→路线或左清单选中工序→三个分区 | 空路线、长名、多前置、无 IPC、历史未标注、只读/停用 |
| 工序编排 | 添加生产/IPC、复制、上下移、显式维护依赖、当前定义保存并回读 | 编码重复、未知/循环依赖、已保存身份保留、失败无部分更新、取消与离开保护 |
| 参数与判定 | 当前工序参数和 IPC 分开维护、合法上下限/单位/方法引用、完成规则安全组合 | 数值/文本切换先确认清除不兼容字段；取消不改变父草稿；旧复杂规则无损保留 |
| 记录表单 | 当前工序显示来源、模板版本、字段数，设计/查看/新建复用既有路由 | 完整分页、加载失败不假空、重试、无权限、未保存新工序不能假绑定、返回定位 |
| CPP/eBR | 进入既有设计器、当前表单规则、角色 ID、保存/重开、独立生命周期入口 | 未保存关闭、403/409/服务失败恢复、历史只读、字段关联与超限动作语义不变 |
| IPC 放行 | 有配置的当前工序按 frozen definition 检查，完成后仅解锁依赖它的后续 | 必检缺失/未复核/签名无效/有效 FAIL 阻断；无 IPC 不制造必检；不能靠类型标签或中文完成文案放行 |

上述是候选验收清单，不能删除或改写原有断言来凑通过。执行门禁可复用原单元/回滚集成测试证明规则，并须以真实5173/8080岗位操作补足页面验收；不得把 Mock 或源码测试称作实际运行页通过。

## 4. 下一阶段实施范围与停止边界

建议本次只批准一个完整原型收拢阶段，最多40分钟、最多3批修正（累计50→53），起点为收到本方案明确批准后的实际开始时间，并记录截止时间。不把此次「完成开发」泛指令自行当作门禁豁免；同根因针对性修复后再现仍停止。

本阶段具体产物：完成与本方案一致的本机 Vue 原型、逐动作真实字段/接口映射、注释设计说明、覆盖正常/异常/恢复与四视口的适用 UI 审查，以及确切源码闭包/hash。既有唯一设计器通过内存适配复用，不复制正式工程或另建测试环境。原型业务值先检查，不写正式 DEV 业务数据。

代码白名单仅为 mes-demo 的 `src/features/processes/ProcessPrototype.vue`、该功能直接依赖/适配与验证文件；文档白名单为该原型设计说明及本功能交接/证据、MES_TASKS、ownership 与现有 Planning。正式 MES 前后端、迁移目录、CI、其他 QC/QMS/WMS/物料任务及本机配置均不在这个阶段的代码修改范围。

原型须自审达到可确认条件后，提交实际源码版本供用户确认；本方案批准**不代签未来未知 hash**。确认后按既有 G3/G3.5 流程冻结接收，再明确正式集成阶段的源文件白名单/预算及新迁移审查，不能越过该门禁直接集成。

## 6. 本轮可确认的决定

确认本方案意味着：采用当前工艺定义并保留 eBR 独立版本；批准名称/说明的上述有界字段方向；批准纠正自动线性依赖、保存身份与恢复语义；批准第4节40分钟/最多3批的完整原型阶段。它不代表整个生产工艺完成、原型最终通过、正式新迁移执行或放宽验收。

若用户要求保留旧原型的工艺受控版本/批准日期，应选择该业务方向并另行形成完整生命周期 DCP，本候选不能隐式恢复。
