# 自动修复20轮门禁调整 — 2026-10-12

状态：`APPROVED / EFFECTIVE`。

批准来源：用户明确要求删除“最多两轮自动修复”规则，调整为超过20轮前必须报告、分析原因并取得批准后再继续修复。

## 生效规则

1. 每个任务首次实现不计轮次；每次失败后的自动代码修复计1轮，最多自动执行20轮。
2. 修复后的针对性验证不单独计轮次；所有轮次、失败签名、修改和验证证据连续累计。
3. 第20轮仍未通过时，在任何第21轮或后续修复前必须暂停并标记`STOP: BLOCKED`。
4. 暂停报告必须包括当前问题、全部尝试方法、每轮关键修改、验证结果、重复失败签名、已排除原因、剩余根因分析、下一阶段最小修复范围和风险。
5. 只有用户明确批准该报告和下一阶段范围后才能继续分析和修复；批准后轮次继续累计，不清零。
6. 禁止通过更名测试、换线程、另开任务、重启代理、降低断言、改变设计契约或跳过检查规避门禁。
7. 相同失败在一次针对性修复后仍复现、设计冲突、越权范围或环境阻断仍须提前停止；20轮不是必须耗尽的目标。
8. 普通UI任务10分钟预算及其他设计、写入、视觉和验收门禁保持不变。
9. 历史报告、旧任务专项授权和已发生的停止事实不追溯改写；新规则从本次批准后用于当前未完成任务的后续修复及新任务。
