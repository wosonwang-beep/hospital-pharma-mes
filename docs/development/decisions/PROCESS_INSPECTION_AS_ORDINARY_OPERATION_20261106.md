# 检验作为普通工序 — 生产工艺界面业务调整（2026-11-06）

状态：**业务方向已确认 / 原型修改完成 / G2专项功能验证通过 / 精确原型版本待人工确认**。

## 1. 用户明确指令

用户明确要求：
- 从整个生产工艺配置中去掉独立的「检验项目」概念/区域；
- 检验只是生产流程中的一道工序，与称量、配制、过滤、灌装、灭菌、包装等工序同级；
- 不在生产工艺页面突出或强化检验，不设置特殊颜色、特殊标签、独立的检验项目表或独立的检验管理入口。

这是一项新的业务表达决策，覆盖旧工序类型 DCP 中「生产工序 / 过程检验（IPC）」的用户界面区分；不回写或篡改旧批准记录。

## 2. 新的用户操作模型

1. 生产工艺仍由工艺定义、适用产品、工序配置、工序数据采集及参数设定方案组成。
2. 工序只有统一的普通工序操作模型；用户通过工序名称、顺序、前置关系、角色、设备、完成条件表达每一道工序。
3. 检验步骤（例如中间检验）作为普通工序出现在左侧工序清单中；与其他工序使用相同的工序设置弹窗、表单列表、设计入口和 CPP 规则入口。
4. 检验记录通过该工序关联的 EBR 表单采集；字段录入校验由字段属性维护；CPP 规则在该表单的 CPP 规则页签定义。
5. 工序级「工艺参数」继续保留，只维护普通工艺参数的采集模式、单位及范围；不再并列展示「检验项目与判定标准」。
6. 不新增全局检验菜单、检验项目配置表、IPC 特殊工序标签/颜色、IPC 专用弹窗或额外检验流程。

## 3. 与既有批准设计的关系

- 生产工艺仍遵循 FINAL BASELINE v1.0.23：当前定义维护；不恢复工艺历史版本、提交审批或批准记录。
- 适用产品仍在生产工艺级维护；一个工艺可适用多个产品，产品通过工艺间接使用相同工序与 EBR 表单。
- EBR 仍以生产批次为中心，表单设计继续复用现有 Canvas/DefinitionDesigner；CPP 继续复用现有 CppRuleDesigner、安全 DSL 和四类已批准超限动作。
- 工艺参数、字段录入校验、CPP 是不同职责：普通工艺参数属于工序配置；基础字段校验属于表单字段属性；CPP 属于当前表单字段组合规则。不得再次引入 IPC 子表作为第三套检验判定配置。
- 既有 QC/QMS 业务单据、请验/取样/检验/报告/QA 放行、独立质量对象及其权限、签名、审计和数据归属不因本次 UI 调整而合并进 EBR，也不被删除。

## 4. 兼容与数据保护

- 旧 DCP-PROCESS-OPERATION-TYPE-001 已批准的 operationType、ipcDefinitions、数据库列、API 字段和历史快照均作为兼容数据保留；不做 UPDATE、回填、删除或历史快照重算。
- 新生产工艺 UI 不再显示/编辑「生产工序 / 过程检验（IPC）」分类，也不再新建独立 IPC 检验项目。
- 对旧定义读取和保存时，正式实现必须保留既有 operationType/ipcDefinitions 原值，除非另有明确数据迁移审批；不得因为新 UI 不展示而把旧 IPC 数据序列化为空并覆盖。
- 现有生产执行、有效 FAIL 阻断、签名、独立复核、前置关系和冻结快照的既有运行行为，本次原型改动不触碰。
- 本次只改 mes-demo 原型和相应设计/验收记录；不改正式 MES 页面、后端 API、数据库、Flyway、权限、历史数据。
