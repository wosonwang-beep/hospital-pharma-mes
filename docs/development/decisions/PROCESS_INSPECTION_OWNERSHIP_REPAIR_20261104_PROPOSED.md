# 工序附属检验原型修正方案

状态：PROPOSED。用户“没有IPC这个过程”的需求已明确；本提案请求的是以下具体样例调整、测试合同纠正和续修范围，不重复询问业务方向。批准本提案也不等于批准尚未完成的原型源码。

## 具体实施结果

保持上方路线带＋左工序＋右配置和UI V2。删除原型中的独立IPC新增入口、生产/IPC类型单选、IPC路线节点特殊标识及“IPC是工艺路线中的工序”提示；统一新增真实工序，原型不再提供IPC工序分类。当前工序仍有工序设置、记录表单、参数与判定，检验项目留在该工序上下文，不新建检验专属路线步骤或菜单。

### 本地样例的明确调整（仅mes-demo内存样例）

1. KCL30-PROC路线由七节点变为六道真实工序，去掉IPC01。OP04灌装的前置从IPC01改为OP03过滤，其余依赖不变；计数从保存路线派生。
2. 模板2104/EBR-KCL30-IPC/INTERMEDIATE_INSPECTION保留身份、名称、定义及草稿状态，仅原型operationCode由IPC01调整到OP03；与现有过滤记录同时显示。此为提出供确认的样例选择，不声称用户曾指定该归属，更不批量改正式记录。历史核对发现正式工艺1检验项挂在OP03，仅作该样例选择参考。
3. 初始parameters为空，不新增伪造检验结果或随意判定标准。验证时在真实工序配置检验项并验证归属保存；该验证数据只在原型内存，先经业务命名检查。
4. 概述改为六道真实工序的描述；不把附属检验作为路线中的一个步骤。当前定义、清场、人员设备要求、表单、CPP及eBR原功能保留。

### 类型兼容边界

本阶段只改原型呈现及直接适配。对新原型工序不再向用户要求PRODUCTION/IPC选择，也不制造IPC类型；既有类型如被读入，以兼容元数据保真，不能用隐藏字段把已存IPC偷偷重写成PRODUCTION或NULL。现正式合同“省略/null保留已存类型”不改变。历史NULL、已有参数/检验/前置和表单关系不能因取消类型选择丢失。

正式ProcessDetailView、后端DTO/实体/API/OpenAPI、数据库列和V071/V074本阶段不改。后续确切原型确认和G3.5后另行完成正式契约变更；存量类型数量、关联快照及消费者需只读核实，不自动转换、删除、合并真实工序或迁移受控记录。
