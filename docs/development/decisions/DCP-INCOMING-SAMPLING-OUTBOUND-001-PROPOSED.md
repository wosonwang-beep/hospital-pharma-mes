日期：2026-10-19；Feature：INCOMING-SAMPLING-OUTBOUND-A-001
业务决策来源：用户在本会话明确确认「取样出库指从待验原辅料批次按实际取样数量扣减库存，关联取样单」。

## 权威与适用边界
FINAL BASELINE COMPLETE v1.0.23、Global UI V2、T1/T2/T3、`docs/development/incoming-approved-chain-contract.md`、`docs/development/decisions/QC_OBJECT_ASSOCIATION_20261011.md`。现有 `qms_inspection_request → qms_sampling_task → qms_sampling_detail → qms_sample → qms_inspection_task → qms_inspection_report` 保留，不新增第二套样品/检验/报告。原物料批次与仓库库存仍由 WMS 唯一持有。

## G0 已批准的业务事实
- 对象：**原辅料待验物料批次**，来源必须为已确认收货单的物料批次，且与取样任务的请验单相同。
- 数量：**实际取样量**，以每条已记录的取样明细合计，按受控单位换算转换为批次库存基本单位；不得用计划量代替。
- 影响：WMS 实物在库数量**减少**，质量状态不因此放行；QA放行和生产可用性保持原独立规则。
- 关联：每条取样扣减记录可回查取样任务、明细、物料批次、容器/库位、操作人和时间。

## G1 产品经理提出、需与原型一起确认的受控实现方案
1. 取样员在既有 T3「取样执行」页逐容器登记实际取样量、取样点、样品分配、复封状态；同页显示“取样出库扣减预览”。**不新增另一张可任意编辑的出库单**。
2. 建议在「完成取样」受控动作中，对本任务的**实际已登记明细**一次性扣减。事务内锁定来源物料批次与库存流水，验证组织、来源、数量、有效单位换算、原库位/容器及库存足额；成功后将不可变取样出库流水与取样完成记录同事务保存。若任一项失败，**整个事务回滚**，取样仍未完成、库存不扣减。
3. WMS 继续唯一拥有 `wms_inventory_ledger`，追加与 `SamplingDetail` 关联的负向业务事件（**事件代码待详细设计确定，不能复用生产领料 ISSUE 或普通调整 ADJUST 冒充取样**）；通过来源明细唯一约束与平台幂等键防重复扣减。历史流水不可覆盖；已完成取样不得普通删除或重新提交。
4. 必须区分**实物库存**与**质量可用库存**：取样可从 BLOCKED 待验库存中扣减，绝不能通过普通生产领料的 RELEASED 资格检查；剩余批次仍 BLOCKED/待验，禁止生产使用。出库仅减少在库量，不增加生产发料量。
5. 原样品分配必须满足 `sum(TEST_SAMPLE,RETENTION_SAMPLE,...)=sampling_detail.sample_quantity`，保留单位和每份样品来源。复封不通过/缺签名/超库存/跨组织/库存不足/单位不精确/并发409，均阻断完成，保留输入并给出字段级原因。
6. 取样完成后详情展示只读「取样出库记录」和流水号、关联明细、数量、单位、库位、扣减前后库存、操作人与时间。禁止前端直接编辑流水或手工改库存。
7. 当前原型只在 `mes-demo` 使用独立浏览器会话数据；**无真实数据库、无正式接口写入**。已存在的 QMS/WMS 页面不因原型修改而重画。

## T1/T2/T3 页面及设计锁
- T1：`#/quality/sampling-outbound/list`，标题「取样出库」，查询条件「物料批号 / 取样任务 / 状态」，重置→查询；记录表展示取样任务、物料、批号、计划/实际取样量、出库状态、操作。
- T2：`#/quality/sampling-outbound/create`，选择已接收请验/可取样任务，自动带出物料批次、生产企业、生产批号、仓库、库存及批准方案；不得人工改批号/库存。
- T3：`#/quality/sampling-outbound/:id`（含执行区域），上部任务/来源只读摘要；中部逐容器实际取样明细（表格）与样品分配；下部扣减预览/检查结果；底部「取消／保存记录／完成取样并扣减」；完成后只读出库流水。**上述新增路由只存在隔离原型，正式路由是否复用现有 `sampling-tasks/:id/execute` 必须在 G3 确认；优先复用该路由。**
- 视口：1774、1440、1280、900；标签与输入同行；表格内部滚动不让页面整体溢出；标准控件32–36px，白卡+浅蓝灰底、蓝色主动作、无额外统计卡。
- 来源：任务/批次/质量标准从现有QMS/WMS实体读取；单位由单位主数据，状态与权限由服务器。**原型中的任务/库存值为构造数据，不是实际供应商或仓库库存事实**。

## 状态/权限/数据/接口差异
- 已有：SamplingTask PLANNED→ASSIGNED→IN_PROGRESS→COMPLETED，Sample CREATED→COLLECTED→RECEIVED，库存 BLOCKED；`qms:sampling:execute/complete`、`wms:inventory:view`，原 WMS Ledger append-only。
- 拟增：QMS 完成取样时调用 WMS 受控内部命令追加取样负向流水，WMS原事务内校验并返回不可变出库事实；不得由浏览器调用通用调整接口。接口、权限、事件类型、来源唯一键及迁移均为**候选，不在原型确认前冻结**。
- 原质量对象字段保持单一 `materialLotId`；取样明细仍以 `samplingTaskId` 和现有明细主键追溯。
- 需设计冻结时具体核对：同批不同库位/容器的余额口径、实际取样的最小单位及换算精度、是否需要独立电子签名含义（可复用取样完成签名时优先复用）、历史记录处理方式、原已完成取样是否追补扣减（默认**不追补历史**，待批准）。
