### V3完整流程（当前原型；下方V2不足说明作为历史）
入口仍#/printing/data-sources。T1源列表的“维护取数来源”进入取数目录T1，新增/维护进入独立T2：名称、GET系统内部接口、响应根路径、记录标识、结构/示例JSON，可新增和修改，识别字段结构后保存重开；不是程序内置两个定义的下拉。模板入口保留现有5173功能。
数据源T2按五段：1基本信息（业务/单据字典、调用页面、编码名称状态）；2主表（维护好的来源、主记录字段、请求参数、试取ID）；3明细（可增多个区域、编码/名称/主表数组路径/行标识）；4关联（可增多个、所属主表或明细、来源/本地键/目标键、一对一或一对多、缺失留空或报错）；5字段（加载组合结构、添加/移除、稳定绑定键/名称/真实来源选择/分组/格式/启停）。底部取消/试取并校验/保存；所有标签控件水平同行，沿用前述Global UI V2尺寸。一对多关联形成自己的记录集合，不笛卡尔乘法扩张原单据明细。
收货实例：收货主记录id101，items明细id1001/1002；supplierId→供应商id、warehouseId→仓库id；每条items.unitId→单位id。数量100.125/20与kg/L逐条关联。出库实例：主记录201，items2001/2002；materialLotId→物料批次id，unitId→单位id，物料名称来自批次materialSnapshot，数量12.5/3。关联真实值不会简单用ID代替名称。
取数引擎仅按来源/路径/关联键/映射配置计算，不含收货/出库业务编码if/switch。示例初始化集中sourceExampleFixtures.ts，运行维护状态保存在独立V3浏览器存储，不覆盖V2或用户原有数据。API地址、根路径、目录、明细、关联、字段修改均会保存；程序固定的是通用GET/路径/关联/格式执行能力，不是业务字段清单。
正式数据设计：统一字典父子项复用；来源目录持久化接口、根、结构元数据和读权限契约；源配置版本保存主表、明细、关联、页面及字段定义。当前版本可维护，模板消费稳定兼容字段投影；改关联/字段含义需新配置版本及模板影响校验，旧发布/签署/归档不重算。正式表/API/迁移待具体原型批准后有界集成，不在本轮创建。正式完整结构来自API/schema或显式授权元数据，不能只按一个非空样本猜字段；源URL须匹配内部已授权GET契约并保留逐条组织/权限/签名校验。
当前原型的来源结构由本地JSON模拟，可编辑新增字段并加载；没有执行输入URL，未连接正式业务接口/数据库。未模拟权限多账号、空数组全量schema、关联链跨多级、集合排序及正式LIST输出，不将这些能力声称为已验收。原型当前覆盖主表/主表嵌套多个明细和明细/主表直接关联；更复杂链可用正式受控投影，但不自动承诺。
