# 统一打印参数与模板识别设计

依据：2026-10-09 用户明确要求「打印单据还是打印列表，应该用程序根据传的参数在打印模板中自行判断怎么显示和识别」。此前将列表/单据作为用户手动选择的两类模板的建议被该要求替代。本文是接口及运行设计草案，不代表当前接口已经支持，也不切换冻结基线指针；实现进度只维护在 MES_TASKS.md。

## 最新方案：由模板打印类型决定输出

用户进一步提出「通过模板加多一个属性，单据类型还是列表类型区分」。据此，首选设计改为模板新增 **打印类型 printType**（DOCUMENT 或 LIST），既有 **单据类型 businessType** 继续表示收货单/检验报告等业务数据源。二者不得重名或混用。

调用者传业务来源、选中 ID 集合或查询范围及模板版本；选定模板后，服务从该版本的受控元数据读取 printType，自动决定排版，无需请求重复声明 outputMode。同一收货单数据源可以建立「收货单据模板」和「收货列表模板」，都走统一管理、字段绑定和打印服务。

| 模板属性 | 多条记录的输出 |
| --- | --- |
| DOCUMENT（单据） | 每条记录填充完整单据及其所属明细，记录之间按模板分页 |
| LIST（列表） | 记录集合填充同一列表，按模板列和分页规则输出 |

若调用入口仍保留两个快捷打印动作，动作只筛选适用 printType；最终模式以服务器读取的模板版本属性为准。不能按记录数量或调用页面推断，也不能让请求中的任意模式覆盖模板类型。每个版本的 printType 随源内容和绑定一同固定，历史版本和归档输出不改写。

此方案替代下文早期「调用参数 outputMode + 同一模板双模式区域」的默认建议。下文保留为讨论历史，实施时不得将两套决策机制并列为 Source of Truth。新增属性的存储、DTO/适用模板返回、校验、旧模板兼容、迁移及 RTM 尚需统一落实；当前只是明确设计方向，没有在现有页面添加未持久化的下拉，也没有修改数据库或 API。

## 早期讨论记录：调用参数决定输出

各业务页面使用同一个打印服务。调用参数明确业务来源、调用场景、记录范围和输出意图。查询页提供「批量打印单据」「打印选中列表」两个动作（可为同一打印按钮的菜单）；动作自动传入输出参数，使用者无需修改模板类别或字段绑定。页面上下文由程序传入，服务端核对授权入口与数据源。

建议请求信息（字段名称为草案，当前 GenerateCommand 尚未扩展）：

| 信息 | 来源和用途 |
| --- | --- |
| businessType | 当前业务的稳定数据源标识，不依赖显示名称 |
| callerContext | 程序传入 QUERY 或 DETAIL，识别调用入口；不决定输出排版 |
| outputMode | 动作传入 DOCUMENTS 或 RECORD_LIST，明确逐单据输出或记录列表输出 |
| templateVersionId | 使用者选择的已发布并启用业务绑定的模板版本 |
| recordId / recordIds / query | 互斥的记录范围：详情 ID、勾选 ID 集合、完整查询条件；保留选中顺序或确定查询排序 |
| formal | 继承既有正式/草稿约束，不由列表参数自动绕过签名或归档规则 |

同一 QUERY 入口、同一组选中 ID 可以请求 DOCUMENTS 或 RECORD_LIST：前者逐条填充完整单据及所属明细，后者填充记录列表。只勾选一条仍遵循动作指定的 outputMode；单据包含多条明细不改变输出意图。记录数量和调用页面均不能单独推断用户要哪一种结果。参数不携带任意 SQL、脚本或前端拼装的业务正文。

## 模板显示及数据绑定

模板仍绑定稳定业务数据源。模板区域可声明受控输出模式、数据区域和循环关系，由统一引擎按 outputMode 显示/隐藏并填充；不复制模板管理功能。一个模板可以同时定义两种模式，也可以只支持一种；适用模板返回时校验请求输出模式，避免套用不兼容内容。

- DOCUMENTS：对选中记录集合逐条填充各自基本信息 + 所属明细，按模板完成一张或多页完整单据，下一条开始新单据。单据详情也通过该模式输出单条记录。
- RECORD_LIST：循环填充选中记录集合，每条作为列表行；按模板的列、汇总和分页规则展示，记录所属明细不会被误当作记录集合。
- 字段目录来自真实业务适配器，支持记录集合、单条记录及记录所属明细的明确关系。参数中的业务标识决定读取哪个适配器，不允许模板自行执行数据库查询。
- 显示规则限定为受控输出模式枚举匹配；调用上下文只用于入口识别/授权，循环限定为登记的数据区域。禁止任意 JavaScript、SQL 或 SpEL。
- 数据由后端按 ID/筛选条件、业务权限及组织范围重新读取。打印全部查询结果保留筛选/排序，不限制为当前页面分页。

## 现有代码差距和实施边界

当前 `/printing/artifacts` 仅接受 `businessType/businessId/templateVersionId/formal`；PrintDataProvider 只提供单个业务 ID 的快照，DocxRenderer 只配置 `items` 循环。前端源选择只涉及已登记检验报告/eBR，WMS 收货尚无打印适配器。因此当前并未实现上述上下文识别、查询范围、嵌套集合或条件区域；不能仅加一个界面按钮宣称完成。

落地需同步明确请求/响应、适用模板筛选、业务适配器、画布区域元数据、DOCX 转换、业务入口、测试/RTM与证据保存契约。旧单据请求和历史 DOCX/PDF 维持兼容。正式批量输出应保留逐单据现有权限、签名、快照和归档证据；查询汇总输出的正式证据语义不能从单据合同自行推定。没有在此文中添加表、迁移、权限、状态或新正式归档规则。

## 核验场景

详情单据/多条明细；查询同一组选中 ID 分别输出多份完整单据和一张记录列表；查询只选一条按两种动作分别输出；跨分页全部结果；来源/模板不匹配；同一模板按 outputMode 显示不同区域；业务权限和组织过滤；旧模板及历史重印兼容。验收采用真实页面、真实后端取数、生成 PDF 与模板参考对照。
