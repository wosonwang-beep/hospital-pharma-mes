# F-004 工序表单来源不可区分 — 产品建议草案

状态：PROPOSED / 待设计确认；不授权正式页面改动或数据库写入。

## 实测问题

2026-10-29，在真实5173/8080、工艺1、OP01工序列表中，前两行显示相同表单名称“称量与投料记录”、表单编码OP01_RECORD、版本V1草稿、字段数23。只读逐行点击证明并非同一模板重复投影：

- 第一行进入模板496，名称“氯化钾溶液批生产记录”，编码 EBR-KCL30-BATCH-RECORD。
- 第二行进入模板291，名称“氯化钾溶液 30ml:3g · 120L 电子批生产记录”，编码 EBR-KCL30-120L-PREVIEW-20261009。

这两个值由现有模板详情读取，用户在工序表单列表无法判断将打开哪份受控草稿；V1只是各自模板的版本，不能用于区分模板身份。记录中的编码为现有数据，只作只读事实引用，不用于新建业务数据。

## 方案比较

推荐候选A：在每个表单行展示其现有eBR模板名称和编码，保留表单名称、表单编码、模板版本、字段数及当前操作；历史名称为空时沿用“未命名（历史模板）”，编码作为区分依据。若空间不足，名称/编码以同一来源信息组完整换行，优先保持行操作可见。模板名称非唯一，不能只显示名称。数据已在现有EbrDetail，无新API/数据库/权限；稳定行标识应包含模板ID与表单编码，避免两模板相同表单编码时复用同一行key。

候选B：列表不展示来源，只要求用户逐条打开查看模板抬头。该方案无需布局改动，但两条同显示值时要求靠试错识别，不能可靠支持工艺维护人员的任务。

上述候选A是产品建议，具体列/区域的视觉形式、长名称、窄屏布局、点击目标、空值和验收应纳入当前批准页面/原型的设计锁核对；模板名称补充授权模板列表、详情和选择器显示，不自动证明此具体工序表单子表的布局已批准。若对既有表格结构属于实质重设计，需按原型优先门禁交付并获确切版本人审；如只构成批准合同内缺陷修正，也须有适用设计确认记录和完整验收证据。不得将本草案写成APPROVED。

## 验证与保护

至少覆盖：同一工序两模板同formCode、名称相同但编码不同、历史空名称、长名、无权限/只读、保存后回读/返回工序，以及四视口标签和表格溢出；对照当前UI V2及精确批准设计，记录真实5173/8080截图与完整mes-ui-ux-audit G5 manifest。仅用独立事务回滚或获准且可定位的数据，保持模板291/496和历史证据不变。前100模板分页截断、请求部分失败属于独立未验证风险，不在本草案中假定新查询API。
