# MES 强制开发与验收规范（仓库级执行门禁）

状态：**MANDATORY / 工程执行规范**。生效：2026-10-09。
适用：本仓库全部后端、前端、数据库、EBR、WMS、QC、QMS、QA、系统管理、打印与测试任务；包括 Codex、远程桌面、ChatGPT/Work 等执行者。

## 0. 权威层级与冲突处理

本文件规定**如何开发和如何证明合规**，不是新的业务/视觉设计权威。
业务与数据：FINAL BASELINE v1.0.23 + 已批准的、明确限定范围的 DCP。
视觉与页面：docs/ui/MES_GLOBAL_UI_DESIGN_SYSTEM_V2.md + docs/ui/MES_PAGE_TEMPLATE_STANDARD_V2.md。
任务/环境/数据库：AGENTS.md、MES_TASKS.md、docs/PROJECT_BASELINE.md。
用户在对话中确认的**具体设计图、交互和字段决策**必须在开发前形成可追溯的“设计确认记录”（见第 2 节），不允许靠模型记忆、口头转述或自行重新设计。
如果旧基线、已批准 DCP、设计图、当前需求互相矛盾，先列出冲突及适用优先级；没有明确授权时 STOP: DESIGN CHANGE REQUIRED。不能暗中选择对开发方便的版本。
特别注意：已批准的 DCP-DATABASE-MENU-AND-USABILITY-001 在其限定范围内允许简单编辑弹窗；不得仅凭通用 T2 规则断言所有弹窗必然违规。对某个页面如用户明确确认独立页面，则先记录该页面的批准范围并按变更流程执行。

## 1. 每次任务的强制启动动作（READ GATE）

**每次收到新开发/修复/审查/测试任务，必须在修改代码前从本机真实文件读取：**
1. AGENTS.md；
2. 本文件；
3. MES_TASKS.md 的相关任务索引与 docs/PROJECT_BASELINE.md 的相关权威路由；
4. 当前任务对应的正式 UI/业务/数据/API/权限规范、已批准 DCP、设计确认记录；只读取相关章节，遵守低 Token 原则；
5. 受影响的现有代码、路由、接口、数据字典、数据库迁移和测试。

不能因为“昨天读过”“聊天里讨论过”“已有记忆”而跳过；读取失败则 STOP: DEPENDENCY_NOT_READY，不允许凭记忆写代码。
在执行记录中写出**已读取文件路径、基线版本、关键约束、冲突结论**。只说“已阅读”而没有路径/约束不算通过。
开始修改前执行 git status，保护现有未提交修改，确认当前任务的文件白名单。

## 2. 设计确认记录（DESIGN LOCK）

每个任务须建立或引用 docs/development/decisions/ 下的单一设计确认记录，记录：
- 任务编号、需求来源/用户确认时间、引用的设计稿文件及版本/截图标识；
- 选用 T1–T6 模板及任何经批准的例外；
- 页面标题、区域顺序、字段清单、标签、控件、字段宽度、按钮位置、交互、PC/移动端布局；
- 字段来源：数据库列/业务实体选择器/数据字典 code/自动计算；不得凭空造字段；
- 查询接口、参数、分页、树联动、空值、状态/权限、允许操作；
- 新增/编辑/查看的页面或弹窗模式及依据；与已有 DCP 冲突必须列明；
- 后端 API、数据库、迁移、签名/审计/冻结快照影响；
- 用户明确确认的验收断言和设计图比对视口；
- 修改范围白名单与禁止修改项。

**聊天里确认的设计，先固化到本记录，再开发**。记录未建立或与确认稿不一致：STOP: DESIGN NOT LOCKED。
实现者不能自行调整字段、模板、间距、控件类型、布局、状态或交互。确需改变时先提交差异与最小 DCP，经授权后同步设计确认记录再施工。

## 2A. 原型驱动开发强制流程（PROTOTYPE-FIRST GATE）

**用户批准日期：2026-10-09。适用于所有新增或重做的 MES 功能页面。**

1. **需求先行**：从正式 PRD、批准的 DCP、业务流程、现有 API/字段/字典/权限及 Global UI V2、T1–T6 获取设计依据；不能由设计工具猜字段或发明业务流程。
2. **完整交互原型**：使用本机独立 `D:\\codex\\_project\\gmp\\mes-demo`（Vue 3 + Ant Design Vue，端口 5174）按功能逐页制作可操作原型；MagicPath 历史已批准版本可作为参考但不再是强制工具，必须包含查询/重置、分页、树、实体选择、字典、表单校验、保存/取消、查看/编辑、空态、错误态、权限表现等当前页面适用的交互。原型可用明确标注的模拟数据，但必须符合真实业务契约。
3. **双重设计交付**：每页同时交付 (a) 不含设计注释的真实业务界面原型，(b) 带尺寸、字段来源、交互流程和验收规则的设计说明图/文档。二者共享同一 DESIGN LOCK，不允许两套相互冲突的规格。
4. **人工确认锁定**：记录本机 `mes-demo` 原型文件路径、Git 提交或内容哈希、5174 访问地址、同视口截图、设计说明文件、T1–T6 模板、字段与 API 绑定、例外和确认时间，状态标为 `PENDING HUMAN APPROVAL`。**只有用户明确确认这一版具体原型及其文件版本**，才能将设计确认记录改为 `APPROVED / FROZEN` 并允许 Codex 将已批准的 Vue 原型集成到正式 MES。确认流程方向不等于确认某一张原型。
5. **Codex 只做工程集成**：以冻结的本机 Vue 3 原型为依据，将已确认的页面结构、组件和交互迁入正式 Vue 3 + Ant Design Vue；复用现有 Global UI V2 组件、路由、权限、数据字典、实体 Picker、API 和状态机。禁止自由重画、擅自改字段/按钮/间距/布局/业务逻辑。若技术适配无法忠实实现，STOP: DESIGN CHANGE REQUIRED。
6. **集成与验收**：对照同一冻结原型逐项验证页面视觉、DOM 几何、所有交互、真实 5173/8080 HTTP、数据库持久化和相关回归。只在所有适用门禁 PASS 后进入 READY FOR ACCEPTANCE；仍须用户最终确认才可 ACCEPTED。
7. **防绕过**：没有本机 Vue 原型已批准的文件版本/哈希 + 设计确认记录，任何执行者都不得以“用户说继续”“已经有一张效果图”“转换很简单”为由直接编写正式 Vue 页面。用户明确批准的紧急缺陷修复或非页面任务不需要新建原型，但仍执行本文件其他门禁。
8. **特殊页面**：Canvas Editor、EBR 目录设计器、打印模板编辑器等应制作覆盖其专用交互的原型和专项验收，不允许简单 CRUD 原型替代。

## 3. 复用检查（REUSE GATE）

编码前列出现有：表/列/索引/FK、字典类型和选项、组件、路由、API、权限、状态机、测试、历史快照。
优先复用；任何新增必须给出“现有能力为何不足”的证据。禁止重复菜单、重复权限体系、重复业务单据和前端硬编码可配置类型。
字典枚举必须绑定统一字典选项 API/组件，验证字典 code、启用状态、选项值与后端允许值一致。组织/部门/用户/产品/物料等实体选择不能伪装成字典。
涉及迁移：查询已执行最大版本、确认无冲突后**只追加新 Flyway**，不得修改已执行文件；保留既有数据与历史证据。

## 4. UI 强制规则（VISUAL GATE）

- 所有查询和表单的**标签与控件必须同一水平行**；空间不足只允许整组换行，禁止标签单独上一行。
- T1 查询区紧凑：输入框不得因 flex:1 或 grid 填满整行；按已确认页面尺寸或合理固定宽度；查询/重置紧跟查询条件。禁止凭空把三个短字段拉成三大列。
- 查询必须真正影响数据；有服务端筛选/分页契约时必须使用服务端接口，不可静默改为全量拉取前端筛选。统计数必须与当前筛选范围一致。
- 新增/编辑/查看严格遵循本任务 DESIGN LOCK 和适用 DCP；不能擅自将独立页面改弹窗或反过来。
- 使用统一 Global UI V2 Token/组件/字体/色彩/间距，不得临时发明视觉风格。
- 受控选项用字典或实体 Picker，严禁写死数据库可配置的下拉值。
- 以真实浏览器 DOM 坐标检查标签与控件中心线、宽度、按钮距离、溢出；PC 至少 1440/1280，窄屏至少 900/375（如页面确认稿另有视口则追加）。
- 有批准设计图时必须在同视口并排截图审查，列出可见差异；“看起来差不多”不是通过标准。

## 5. 实施边界（WRITE GATE）

先提交“将修改哪些文件/为何修改/不会修改哪些文件”的清单。只修改白名单内文件；超出范围停止并更新影响分析。
不改已冻结业务规则、签名、审核、审计、状态、路由、权限、API、数据库，除非有明确授权。
不得为了通过测试而降低断言、删除失败测试、伪造测试结果或用 mock 冒充真实接口验收。
不允许擅自清理用户的未提交文件、重置数据库、覆盖历史记录或提交/推送 GitHub。

## 6. 验收门禁（ACCEPTANCE GATE）

按任务风险执行并留证据，适用项缺一即 FAIL：
A. 设计一致性：逐项对照 DESIGN LOCK 的字段、页面模板、按钮、控件、布局与交互；差异清单为零或全部经授权。
B. 静态与构建：TypeScript typecheck / 前端 build / Java 编译；权限、字典、路由、接口契约静态核查。
C. 功能：查询、重置、筛选、分页、树联动、新增、编辑、查看、保存后重读、空态、校验、权限正反例；真实 HTTP 参数与返回值可查。
D. 数据：数据库实际持久化、关联/FK、字典项、迁移 validate、事务与并发；测试保留/回滚遵守 AGENTS.md。用户明确要求保留的测试数据需有专门标识且不删除。
E. 视觉：真实本机 5173 页面 + 8080 API，PC/移动端截图、DOM 几何断言、与批准设计图同尺寸对照；仅 mocked Playwright 或页面可打开不能算真实验收。
F. 回归：受影响模块及直接依赖的单元/集成/浏览器测试；全系统回归只在明确里程碑或用户要求时执行。
G. 结果：记录测试命令、退出码、通过/失败/跳过数、失败根因、截图/日志路径、剩余风险；不得只写 PASS。

**FAIL 处理**：发现偏差先归类为“实现错误 / 设计冲突 / 测试错误 / 环境错误”，仅在已批准范围内修复后重新运行相关门禁；未实际运行不能宣称已验证。
**状态定义**：NOT STARTED → IN PROGRESS → BLOCKED / READY FOR ACCEPTANCE；只有用户明确批准后才可写 ACCEPTED。任何关键项未通过必须标记 BLOCKED 或 IN PROGRESS。

## 6A. 自动质量门禁防死循环（ANTI-LOOP GATE）

本节为 2026-10-09 用户明确授权的**强制配置**，适用于所有自动修复与重复验证任务。此节约束自动化行为，不替代第 6 节验收要求。

- **自动修复上限：2 次。** 每个任务最多执行 2 轮自动代码修复（首次实现不计入；每轮失败后的代码修复计 1 次）。修复后的针对性验证不另计修复次数；达到上限仍不通过时立即 STOP: BLOCKED，不得重置计数、换测试名称或重新启动代理绕过限制。
- **普通 UI 任务时间上限：10 分钟。** 从开始自动实施/修复至验证结束的单任务墙钟预算为 10 分钟，包含等待、修复和重测。达到上限立即停止新修改和新测试，安全结束当前可中断任务，记录未完成项；不得以延长等待、后台继续工作或新开会话绕过。复杂集成/迁移/打印等非普通 UI 任务需在 DESIGN LOCK 中预先定义独立预算，不自动套用 10 分钟，也不得无限运行。
- **重复错误提前停止：是。** 记录失败签名（测试标识 + 失败断言/错误码 + 关键堆栈或 DOM 位置）；相同签名在一次针对性修复与重测后仍出现，立即 STOP: BLOCKED，不继续尝试第二种盲目补丁。相同根因的不同报错也应合并判断。
- **禁止自动修改设计契约和验收断言：是。** 自动修复不得编辑已批准的设计确认记录、冻结基线、验收标准、测试断言/阈值、跳过条件或质量门禁配置，不得删除失败测试或改用 mock 冒充真实验收。若证明测试契约错误，停止并提出有证据的变更申请；仅用户明确批准后可单独修改受控契约，且不能作为当前失败的自动修复。
- **先分类再决定是否修复。** 实现错误：在任务文件白名单内有限修复；设计冲突/越权修改/需要新增迁移或 API 权限：立即 STOP: DESIGN CHANGE REQUIRED；环境异常：诊断并报告，不能改业务代码“绕过”；测试契约错误：停止核对基线，不能自行改断言。
- **特殊页面不豁免验收。** Canvas Editor、EBR 目录、T4 执行工作台、T5 审核、Word/PDF 模板设计器可以在事先批准的 DESIGN LOCK 中使用专用几何、交互和证据规则；不能因不适合通用 CRUD 检查就直接 SKIP。
- **每轮必须留证据。** 记录开始时间、预算、修复次数、失败签名、具体修改文件、执行命令/退出码、前后差异、终止原因。PASS 仍须通过第 6 节所有适用门禁；预算用尽或重试停止只能报告 BLOCKED/IN PROGRESS，绝不可写 PASS/READY FOR ACCEPTANCE。
- **不可自动递归。** 自动门禁只执行当前任务，不自动生成新任务、调用自身或自动开启下一轮代理会话。任何需要扩大时间预算、增加修复次数或修改本节的请求，必须由用户明确批准。

## 7. 强制交付格式

每次任务报告必须包含以下五栏，不得省略：
1. 基线依据：真实读取的文件、版本、设计确认记录；
2. 设计差异：规范要求 / 当前实现 / 违反项 / 已改文件；
3. 修改范围：实际修改文件列表、迁移号、保留的用户数据；
4. 验收证据：每个门禁 PASS/FAIL/NOT RUN，命令、数量、截图和日志；
5. 结论：READY FOR ACCEPTANCE / BLOCKED / IN PROGRESS；尚未完成与禁止宣称的事项。

## 8. 不可绕过条款

- “继续”“直接开发”“严格按图”“验收”不代表免读文件、免设计锁定或免验收。
- 若对话里已确认设计而仓库未固化：先补设计确认记录，不能凭模型记忆施工。
- 自动化脚本/CI 应检查本文件与设计确认记录的存在和适用项；静态检查不能证明视觉合规，必须补真实浏览器证据。
- 发现违反本规范时应报告具体条款，禁止用“编译通过”代替验收。
- 修改本文件或放宽门禁需要用户明确授权，并保留变更记录。
