# MES 工作流受控变更

显式启用技能时适用，继承 AGENTS.md / MES_DEV_RULES.md，**不新增业务设计权威或改变既有规定**。

冻结设计/原型/字段/数据库/API/权限/状态/GxP 或验收规则需要变更时，停止并提出 RFC/Design Change；附批准依据、当前版本/哈希/提交、最小变更范围、冲突、影响的页面/实体/字段/API/权限/测试/依赖及无变化项目。未批准不得改冻结内容、调阈值、skip 或绕测试。

真实人类/已明确授权的设计主体批准具体 RFC 后，将批准原文及可核验来源保存现有 decisions/批准 DCP 位置。对照数据库、域、状态机、API/OpenAPI、UI、权限、测试、RTM、迁移、集成/任务依赖逐项同步；保留历史冻结 release 和执行过的 Flyway 原封不动；新增物理迁移版本依真实成功历史，不运行 repair/clean。生产/eBR 的审计/签名/修订/lineage 不能被基础维护例外吞并。

重新打开最早受影响阶段及后续阶段：创建新 revision 的任务清单，旧 workflow.yaml/签名/冻结证据留不可覆写历史文件（带原 SHA256）。在同一 feature 内登记 RFC 和批准，不创建另一业务 Source of Truth；更新引用和冻结 ID。`advance` 不允许从 ACCEPTED 自动重开，需经审查的人工 revision 编辑；新 subject 使旧批准和执行报告失效，必须重跑受影响门禁和回归并重新签名确认。状态链不能靠改 ACCEPTED 字符串绕过签名/hash。

切换权威 pointer 前必须完成跨文档一致性审查；若发现超出批准范围的新问题再次 DESIGN CHANGE REQUIRED。外部权限、真实设计/原型批准、破坏性操作没有授权必须保持阻断，不能通过模拟数据假装批准。

工作流自身修复只可调整安装新增文件；本次用户允许反复修复和重测自身问题，不能借此修改既有规范、冻结设计、业务代码或弱化业务验收。测试 fixture 的 WF-TEST-*、签名身份、伪业务产物全部标 SIMULATION 且临时保存；不得写入真实 MES 任务 ACCEPTED。
