# eBR book implementation plan

Execution method: native implementation in this delegated session as explicitly requested by user; design and review belong to parent assistant. Prior approval covers implementation, required DEV database additions and local backend update.

Goal: one reusable variety book across specification products, batch-scoped filling/packaging records, actual referenced evidence and immutable printable book.
Architecture: extend existing release snapshot, eBR runtime and reporting adapters. Add typed directory contract, versioned book storage and book PDF manifests in mes-release; retain owner-module truths and existing signature gates.
Spec: docs/architecture/EBR_BOOK_DCP_2026-10-08.md

Constraints: Java21/SpringBoot3/Vue3/UI V2; native DEV3306, existing Redis6379; migrations append-only; no key generation/push/external deploy.

1. Typed BookDefinition validation and tests: explicit closed mappings/items; invalid fields, duplicate/order, required/count, scope and cross-spec form mismatch reject.
2. V035 templates/snapshots/PDF manifests and shared form uniqueness; production snapshot port freeze; eBR scoped-form resolution. Test legacy isolation and batch-shared vs operation scopes.
3. BookTemplateService publication validation, safe stored layout and template listing/editor; audit/idempotency/version locking. Validate product/process identities and print version IDs.
4. BookSourceAdapter read owner facts per permission; BookService directory/status and rendering. Test denied source, empty/required, stable ordering, revisions and lack of fake signatures.
5. DOCX whitelist adapter and PDFBookComposer cover/contents/body/attachments/evidence, bookmarks/page numbers; immutable PDF history/reprint. Test actual converters, multipage Chinese and source-change generations.
6. Vue book/template pages and existing batch entry route. Type/build and browser directory/form links/PDF/rejection checks.
7. DEV backup/history validation, Flyway upgrade, rollback-safe DB tests, JAR build and local deployment health. Record exact evidence and incomplete gates; update API, RTM and MES_TASKS.

Review focus: historical batches without new mapping stay legacy; two execution units share exactly one BATCH form; each source access is enforced at read/export/reprint; missing facts never imply normal/complete; changed source cannot alter old PDF.
